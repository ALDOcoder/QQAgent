# 一条消息的一生（架构说明）

> 对应日志：`12:34:12 进来 ... text=你是谁呀？` → `12:34:14 发送 ... HTTP 200`

## 一句话纠正

**QQ 从来不访问我们的后端。** 整条链路里所有连接都是**我们主动连出去**的——所以 `ECS` / 家用路由的安全组一个入站端口都不用开，笔记本也没有公网 `IP` 也无所谓。这不是巧合，是官方路线的设计前提：腾讯没法主动连进你家里。

## 两条连接（关键：不是一条）

很多人以为"连上了就一直用同一条通道收发"，实际是两条**互相独立**的连接：

| | 长连接（收） | 短连接（发） |
|---|---|---|
| 协议 | `WSS`（WebSocket） | `HTTPS POST` |
| 方向 | 我们 → `wss://api.sgroup.qq.com/websocket` | 我们 → `https://api.bot.qq.com/v2/users/.../messages` |
| 谁发起 | **我们**拨出去，之后保持不断开 | **我们**每次发消息新建一次 |
| 内容 | QQ 把事件**顺着这条已建立的通道推下来** | 我们主动提交"要发的内容" |
| 代码 | `GatewayClient` | `QqMessageSender` |

**收和发走的是完全不同的两条线，只是共用同一个 `access_token`。**

## 完整时序

```
1. 启动时：我们 GET /app/getAppAccessToken     → 拿 access_token（约 2h 过期）
2. 我们 GET /gateway                            → 拿 wss 地址
3. 我们连上 wss                                  → 一条长连接建立
4. QQ 推 op=10 Hello{heartbeat_interval:41250}  → 我们回 op=2 Identify{token,intents}
5. QQ 推 op=0 READY{session_id}                  → 订阅生效
   —— 此后每 41s：我们 op=1，QQ op=11（心跳保活）——

【你发"你是谁呀？"的那 2 秒】
6.  你的 QQ 客户端 → 腾讯服务器                    （这段是腾讯内部，跟我们无关）
7.  腾讯服务器匹配到这个机器人订阅了 C2C 事件
8.  腾讯服务器 **顺着第 3 步那条已建立的长连接**，往下推 op=0 t=C2C_MESSAGE_CREATE
9.  GatewayClient 收到 → EventDispatcher 解析 d.content / d.author.user_openid / d.id
10. ReplyPolicy 查白名单 → EchoBrain 生成回复文本（现在只是 echo，P4 换成大模型）
11. QqMessageSender **另开一条 HTTPS POST** /v2/users/{openid}/messages，带 msg_id 和 token
12. 腾讯收到 POST → 把它当作机器人发的一条新消息 → 推送到你手机
    （第 11/12 步之间我们收到 HTTP 200 + 消息 id，这就是"腾讯收下并受理了"）
```

## 回答你原话里的三个点

- 「**他返回消息之前，是访问到了我们的后端吗？**」
  **不是。** 第 8 步是数据从腾讯流向你，但走的是**第 3 步你自己拨出去、并且一直没断的那条 socket**。它没有"找到"你，是你一直站在门口没走。
- 「我们的后端经过逻辑处理后返回给 QQ」
  对，第 9→11 步。注意**返回是另外拨一条 `HTTPS`**（第 11 步），不是顺着长连接往回写。
- 「然后通过 QQ 发给我」
  对，第 12 步。你的客户端与腾讯服务器之间那一段完全是腾讯自己的协议，我们看不到也管不着。

## 为什么这么设计

`WebSocket` 存在的意义只有一个：**服务端需要能在任意时刻主动推事件给你**。
如果不用长连接，就得反过来——你给腾讯一个公网 `HTTPS` 回调地址，让腾讯来连你。那就是"回调模式"，需要你有公网 `IP`/域名和证书。`WebSocket` 让一台在家拨号、藏在路由器后面的笔记本也能当服务器，代价是：你必须自己处理心跳（`41250ms`）和断线恢复（`op=6 RESUME` + `session_id`）——这两个在 `GatewayClient` 里都实测跑通了。

## 时序图（每条线标了发起方）

图例：`──▶`/`◀──` = `HTTPS` 短连接（一次请求一次断开）；`══▶`/`◀══` = 那条唯一的 `WebSocket` 长连接；★ = 本进程内方法调用，**没有任何网络**。

```
   你的 Java 进程                                    腾讯服务器
   （笔记本，无公网 IP）
────────────────────────── 阶段一：启动，只做一次 ──────────────────────────

 ①  GatewayClient / AccessTokenService
    │─── GET https://api.bot.qq.com/app/getAppAccessToken ───▶│  发起方：我们
    │◀── access_token（expires_in ≈ 7200 秒） ───────────────│   新拨一条 HTTPS
 ②    GatewayClient
    │─── GET https://api.bot.qq.com/gateway   [Authorization: QQBot <token>] ─▶│  发起方：我们
    │◀── {"url":"wss://api.sgroup.qq.com/websocket"} ─────────│   新拨一条 HTTPS
 ③    GatewayClient.buildAsync(...)
    ═══════ 拨出 WebSocket，此后一直不挂断 ═══════════════════▶│  发起方：我们 ★全程唯一的长连接
 ④  ◀══ op=10 Hello {"d":{"heartbeat_interval":41250}} ══════│  发起方：腾讯（在③上往下推）
 ⑤  ──══ op=2 Identify {"token":"QQBot <token>","intents":33554432,"shard":[0,1]} ═▶│  发起方：我们（在③上往回写）
 ⑥  ◀══ op=0 READY {"d":{"session_id":"…"}} ═════════════════│  发起方：腾讯 → 订阅正式生效
 ⑦  每 41.25 秒循环：──══ op=1 HEARTBEAT {d:seq} ═══════════▶│  发起方：我们
 ⑧                ◀══ op=11 HEARTBEAT_ACK ═══════════════════│  发起方：腾讯

─────────────────── 阶段二：你在手机发"你是谁呀？" ───────────────────

 ⑨  手机QQ ──(腾讯私有协议，我们看不到/管不着)──▶ 腾讯服务器
 ⑩  ◀══ op=0 t=C2C_MESSAGE_CREATE {"d":{"content":"你是谁呀？","author":{"user_openid":"56E3A5…"},"id":"ROBOT1.0_…"}} ══│
        发起方：腾讯 ★★ 走的是第③步那条【你自己拨出去、一直没断】的老线
        它没有拨号、没有找到你、没有连接你 ——
        命中断点的是本进程 HttpClient 的读线程 `client-3-Worker-0`

──────── 阶段三：本进程内部处理（同一线程，★全程无网络发生★）────────

 ⑪  ★ GatewayClient$FrameListener.onText → handleFrame
      ★ EventDispatcher.dispatch → onC2c → new InboundMessage(openid, msg_id, text)
      ★ ReplyPolicy.allow(openid)  查白名单
      ★ EchoBrain.reply(msg)  → "收到: 你是谁呀？"      （P4 换成大模型）

──────── 阶段四：把回复发出去（这是第 2 次拨号，另开一条线）────────

 ⑫    QqMessageSender.replyC2c(...)
    │─── POST https://api.bot.qq.com/v2/users/56E3A5…/messages ─▶│  发起方：我们
    │    body {"content":"收到: 你是谁呀？","msg_id":"ROBOT1.0_…","msg_type":0}  ★新拨 HTTPS，不是顺着⑩往回写
    │◀── HTTP 200 {"id":"ROBOT1.0_YZ…","timestamp":"2026-10-31T12:34:14"} ─│  腾讯已受理
 ⑬    腾讯 ──▶ 推送到你手机，显示成机器人的一条新消息
```

### 「谁发起」速查表

| 线 | 内容 | 发起方 | 连接类型 | 代码位置 |
|---|---|---|---|---|
| ① | 换 `access_token` | **我们** | `HTTPS` 短 | `AccessTokenService` |
| ② | 问 `wss` 地址 | **我们** | `HTTPS` 短 | `GatewayClient.fetchWssUrl` |
| ③ | 建立 `WebSocket` | **我们** | `WebSocket` 长 ★唯一 | `GatewayClient.doConnect` |
| ④⑥⑧⑩ | `Hello`/`READY`/`ACK`/**事件** | **腾讯** | 都在 ③ 这条线上流动 | `FrameListener.onText` |
| ⑤⑦ | `Identify`/`HEARTBEAT` | **我们** | 都在 ③ 这条线上写回 | `send(frame, ws)` |
| ⑫ | 发送回复 | **我们** | `HTTPS` 短（新拨） | `QqMessageSender.replyC2c` |

**全表只有一行是"腾讯主动找你"**：④⑥⑧⑩ 那一组。而它们的载体是③——你自己拨出去的那条 socket。本进程里唯一接受外来连接的是 `Tomcat`（只服务 `127.0.0.1:8080` 的 `/debug`），它在这条链路里一次都没被腾讯用到。

### 要背的就两句

1. **收 = 一条长连接**（③ 建立，之后腾讯在上面往下推、我们在上面往回写心跳）。
2. **发 = 一次独立拨号**（⑫ 每次新建 `HTTPS`，跟长连接无关，只共用 `token`）。
